# buffetkimz.com 콘텐츠 자동화 A to Z

이 문서는 `buffetkimz.com`의 글·계산기·일정·자료앨범을 **매일 한 번의 파이프라인으로 생산**하기 위한 영구 지침서다.
기계가 읽는 원천 목록은 `automation/sources-catalog.json`(336개), 실행 코드는 `automation/tools/`와 `scripts/`에 있다.

## 0. 왜 기존 방식을 폐기하는가

기존 방식은 **남이 요약한 뉴스를 다시 요약**하는 3차 가공이었다. 그 결과 세 가지가 반복됐다.

1. **숫자가 틀린다** — 기사에 적힌 세율·한도가 원문(법령·보도자료)과 어긋나도 확인할 방법이 없었다.
2. **모두 같은 말을 한다** — 같은 통신 기사에서 출발하면 5개 채널의 콘텐츠가 한 문장으로 수렴한다.
3. **시간이 지나면 죽는다** — 시행일·발표일이 바뀌어도 기존 글은 옛 기준으로 남는다.

그래서 원칙을 뒤집는다. **"요약을 요약하지 않는다. 1차 원천을 직접 읽고, 하나의 근거를 4곳에 동시에 꽂는다."**

## 1. 다섯 가지 대원칙

| # | 원칙 | 판정 기준 | 위반 시 |
|---|---|---|---|
| P1 | **1차 원천 직독 + 정보창고 1차 저장** | 인용한 모든 수치에 `sources-catalog.json`의 `id`가 붙어 있고, 웹사이트로 나가는 모든 자료는 반드시 **우리 정보창고(Google Drive `버핏킴즈 정보창고`)를 거쳐 1차 저장한 뒤** 사이트에 반영한다 | 발행 보류 |
| P2 | **숫자 단일 출처** | 계산에 쓰는 상수는 `src/data/tax-rules.ts` 한 곳에서만 온다 | 게이트 실패(`npm run verify:tax`) |
| P3 | **OSMU 4연동** | 하나의 근거가 글·계산기 변수·일정·자료앨범 4곳에 동시에 반영된다 | 발행 보류 |
| P4 | **95점 게이트** | 아래 6개 루브릭 합계 95점 미만이면 라이브 반영 불가 | 반려·재작업 |

> **무중단 자동화 경계 (2026-11-22 대표님 지시 반영)**: 웹사이트 콘텐츠·오늘 허브·자료 갱신은 **우리 정보창고 1차 저장**을 거친 뒤 **95점 게이트 + 전수 검증(오류 0건) 100% 통과 시 대표님 개입 없이 자동 빌드·라이브 반영**된다. 반대로 **1건이라도 검증 실패·수치 불일치 시 배포를 즉시 차단**하고 보반과장과 뮤즈대리, 김대표님께 경보만 보고한다. **보반과장·뮤즈대리는 전 구성원의 임무를 파악해 마감 10분 전부터 미시행 시 1분 단위로 독촉 관리하며, 웹사이트 갱신 차질 시 두 총괄책임자 역시 경질 대상이다. 나머지 전 구성원은 웹사이트 운영 임무가 최우선이며, 이 임무를 이행하지 못할 시 즉시 영구 퇴출된다.** (대외 발송인 SNS·이메일 소식지는 별도 승인 경계를 유지한다.)

## 3. A to Z 7단계 파이프라인

```text
[S1] 05:00  소싱        collect_sources_sample.py  → 원천 아이템 JSON
      │
[S2] 05:30  필터링      중복 · 시행일 · 트렌드 · 금지주제 차단
      │
[S3] 05:45  소재 확정   앵글 1개 · 근거 1~3개 · 4연동 대상 지정
      │
[S4] 06:00  4종 생성    자산리포트 + 앱스토어 변수 + 골든타임 + 자료앨범
      │
[S5] 06:30  95점 게이트 세법·수치·출처·비중·문체·모바일 (인스팅대리)
      │
[S6] 07:00  빌드·검증   publish_pipeline → npm build → verify_tax → verify_pipeline_v2
      │                (라이브 반영은 95점+오류 0건+2-Key 통과 시 자동)
      │
[S7] 주간·월간 사후     링크·소스 신선도 재검증, 성과·로테이션 점검
```

### S1. 05:00 — 소싱 (원천 수집)

- **명령**: `python3 scripts/collect_sources_sample.py --days 1 --limit 15`
  - 정식 운영에서는 `--limit`을 30~40으로 올리고, API 키가 필요한 소스(ECOS·KOSIS·DART·FRED·EIA·국토부 실거래가)는 환경변수로 주입한다.
- **수집 창**: 기본 1일. 발표 주기가 긴 기관(연준·BLS·IMF)은 3일 창으로 별도 실행해 '지연' 표시로 붙인다.
- **우선순위**: RSS/API 먼저, HTML은 상세 확인용. 공공 API > 기관 보도자료 > 1차 통신 > 언론.
- **필수 기록**: `source_id`(카탈로그 id), 제목 원문, 발표일(UTC→KST), 효력일/기준기간, 단위, **잠정/확정 상태**, URL, 요약.
- **산출물**: `automation/output/collected-YYYYMMDD-HHMM.json` + `.md`
- **폴백**: 재시도 2회 후 curl 폴백 → 같은 분야 2순위 소스 → 그래도 실패하면 그 슬롯을 비우고 보고서 `sources_failed`에 남긴다. **빈 슬롯을 추정으로 채우지 않는다.**

### S2. 05:30 — 필터링 (중복·시행일·트렌드)

| 필터 | 규칙 | 판정 예 |
|---|---|---|
| **중복·Delta 게이트** | URL 정규화 + 제목 정규화(공백·기호 제거) + 최근 14~30일 내 동일 주제는 **새 시행일·새 수치·새 판례** 중 최소 1개 변동(Delta)이 없으면 자동 HOLD | 같은 금통위 결정을 3개 매체가 써도 1건만 통과, 변동 없는 재탕 차단 |
| **시행일** | 법령·제도는 `시행일` 필드가 없으면 보류. 이미 시행된 것은 '지난 기준'으로 표기하고 새 기준이 있으면 새 기준 우선 | 2027년 시행 예정 제도는 '예정' 라벨 필수 |
| **트렌드** | 네이버 데이터랩·Google Trends 급상승 + 5대 채널 신규 영상 반응을 가점(최대 +10점) | 트렌드만 있고 1차 근거 없으면 **탈락** |
| **금지 주제** | 단기 시황 중계, 종목 매매 추천, 보험사·상품 홍보, 미확인 특정인 비방 | 즉시 차단 |
| **비중** | 최근 10편 메인(금융·투자·연금·노후·경제) 80% 목표, 보험 20% 초과 시 경고 | `publish_pipeline.py ratio` |

- **산출물**: 통과 목록 + 탈락 사유표(탈락도 기록해야 다음 날 같은 소재를 다시 집지 않는다).

### S3. 05:45 — 소재 확정·앵글 설계

- 통과 목록에서 **오늘의 1~3건**만 고른다. 많이 쓰는 것이 목표가 아니다.
- 각 소재마다 3줄을 확정한다.
  1. **근거**: `source_id` + 원문 문장(인용 아님, 우리 말로 요약)
  2. **판단**: 독자의 돈에 어떤 차이가 생기는가(한 문장)
  3. **연동**: 4곳 중 무엇을 어떻게 바꿀지(예: 예금 계산기 기본금리 갱신)
- **앵글 3안**을 부이대리가 만들고, 보반과장이 1안을 고른다. 채택 사유를 한 줄 남긴다.
- **산출물**: `drafts/YYYY-MM-DD-<slug>.plan.json` (근거·앵글·연동 계획)

### S4. 06:00 — 4종 동시 생성 (OSMU)

하나의 근거에서 4개 산출물을 **같은 커밋·같은 기준일**로 만든다.

| 산출물 | 위치 | 필수 요소 |
|---|---|---|
| **① 자산리포트 글** | `src/content/posts/<slug>.md` | 제목·요약(80자)·카테고리·기준일·1차 출처 2개 이상·표 1개 이상·면책 1회 |
| **② 앱스토어 계산기 변수** | `src/data/tax-rules.ts`(세율·한도) · `src/data/apps.ts`(설명) · `src/data/utils-*.ts`(도구 정의) · `src/components/tools/ToolRunner.tsx`(렌더) | 변수 이름·단위(만원/원/%)·출처 id·'참고용 모의계산' 고지 |
| **③ 골든타임 일정** | `src/data/calendar.ts` | 발표일·시행일·마감일, D-day 산식, 원문 링크 |
| **④ 자료앨범 카드** | `src/data/gallery.ts` + 이미지 | 6장 1세트, 장당 한 문장, 3D 클레이 캐릭터 일관성, 1080×1350 |

- **작성 규칙**: 원본 제목을 그대로 쓰지 않는다. 숫자는 '기준일'과 함께 쓴다. 세법·보험 글은 가입 세대·소득 구간 등에 따라 달라지므로 **적용 조건 2줄 + 계산기 대입 링크**를 필수 동반한다. 12~18자 호흡으로 줄바꿈(모바일).
- **산출물**: 초안 4종 + `source_ref` 메타(4곳에 동일 id) + **Claim Ledger**(주장 1건당 1차 출처 URL·기준일·수치 매핑표).

### S5. 06:30 — 95점 게이트

인스팅대리가 6개 루브릭으로 채점한다. **한 항목이라도 0점이면 총점과 무관하게 반려**한다.

| 루브릭 | 배점 | 0점 조건(즉시 반려) | 확인 방법 |
|---|---:|---|---|
| 수치 정확성 | 25 | 원문과 다른 숫자 1개 | 원문 대조표 |
| 법령·시행일 | 20 | 시행일 미표기 또는 폐지 법령 인용 | 국가법령정보센터 |
| 1차 출처 | 15 | URL 없는 수치 | `source_id` 역추적 |
| 4연동 일치 | 15 | 글·계산기·일정·카드의 숫자가 다름 | `npm run verify:tax` |

- **합격선**: 95점 이상. 90~94점은 보반과장 재량으로 1회 수정 후 재채점, 90점 미만은 S4로 반려.
- **기존 아카이브 기준선(2026-11-22)**: `validate` 결과 **error 0건 정리 완료**(2026-11-22). 기존 8건(태그 4개 6편 → 핵심 3개로 축약, 빈 대괄호 체크리스트 1건 → 번호 목록, 금지어 `무조건` 1건 → 조건부 표현)을 본문 수정으로 해소했고, 게이트는 이제 신규·기존 글 모두 **error 0**을 기준으로 본다.
- **자동 명령**: `python3 scripts/publish_pipeline.py validate --json` · `npm run verify:tax` · `python3 scripts/verify_pipeline_v2.py` + **계산기 fixture 회귀검증**(대표 입력값별 예상 결과 대조)

## 부록 B. 소스 추가·교체 절차

1. `automation/tools/catalog_data/catN_*.py`에 항목 추가(이름·URL·방식·주기·섹션·담당·메모).
2. `python3 automation/tools/build_catalog.py --check` — 중복 URL·필드 누락 0 확인.
3. `python3 automation/tools/build_catalog.py` — JSON·MD 재생성(기존 verify는 URL 기준으로 보존).
4. `python3 automation/tools/verify_catalog.py --retry-errors` — 신규·실패 항목 실측.
5. `OK` 또는 `KEY/차단`이면 등록 완료. `404`면 즉시 교체, `ENV`면 메모에 환경 제약 명시.

## 부록 C. 이 문서의 개정 규칙

- 숫자·기준이 바뀌면 **부록 A와 카탈로그를 같은 커밋**에서 갱신한다.
- 단계·담당이 바뀌면 `version`을 올리고 변경 사유를 한 줄 남긴다.
- 이 지침서와 실제 코드가 다르면 **코드가 아니라 이 문서를 고친다**(문서가 기준).
